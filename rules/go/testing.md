# Go testing

- Tests live next to the code in `_test.go` files; use `package x_test` for black-box API tests.
- Table-driven tests with `t.Run(tt.name, ...)` for input variations.
- Name tests `TestUnit_Behavior` / `TestUnit_Behavior_Condition`.
- Use `t.Helper()` in helpers, `t.Cleanup()` for teardown, `t.Parallel()` when tests are isolated.
- Fail with useful messages: `t.Fatalf("status = %d, want %d; body = %s", got, want, body)`.
- Use the standard library or the repo's chosen assertion package; do not add a second one.
- Handler tests use `httptest.NewRecorder` / `httptest.NewServer` through the real router.
- Store and service tests run against real Postgres (testcontainers-go or the compose DB) with
  migrations applied; never mock sqlc queries.
- Fake outbound HTTP with `httptest.NewServer`, not by patching globals.
- Inject clocks and ID generators; no `time.Sleep` in tests.
- Always run `go test -race -count=1 ./...` before finishing.
- Check coverage of changed packages with `-coverprofile`; cover error branches.
- Use build tags or `testing.Short()` to separate slow integration tests if the repo does.
- Do not use `t.Skip` to hide a failing test.
- Golden files are regenerated by an explicit flag (`-update`), and reviewed in the diff.
- Use `go test -run` and `-fuzz` for parsers and validators handling untrusted input where useful.
- Keep test helpers in `internal/testutil` (or the repo equivalent), not duplicated per package.
