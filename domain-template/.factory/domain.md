# Domain harness

Every factory agent reads this file. It overrides generic advice from the base harness.
Keep it short, specific, and true. Delete these instructions when you fill it in.

## What this product is
One paragraph: who uses it, what it does, what matters most (e.g. correctness of money, privacy).

## Glossary
- **Term** — meaning in this business (and what it is NOT).

## Invariants (never break)
- e.g. A paid invoice is immutable.
- e.g. Every query on tenant data filters by `tenant_id`.

## Critical data / high-risk areas
Changes here are always `high` risk:
- e.g. `backend/internal/billing/`, `backend/internal/auth/`

## Architecture
- Frontend: React + Vite + TypeScript in `frontend/`. Talks to backend only via HTTP API.
- Backend: Go in `backend/`. SQL in `backend/db/queries`, generated by sqlc into `backend/internal/db` (never hand-edit).
- Migrations: `backend/db/migrations`, new file per change, never edit applied ones.

## Conventions
- Errors, logging, naming, API style, folder layout specific to this repo.

## Test data & environments
- Test accounts QA may use on dev/stg (no real customer data, no credentials here — reference env var names).
- Never run anything against production.
